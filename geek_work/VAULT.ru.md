# Локальная Markdown-проекция Digital Brain

`geek_work_vault.py` экспортирует выбранную часть графа в новый каталог,
который можно читать обычным редактором Markdown или открыть как Obsidian vault.
Установка Obsidian/Hermes, плагины, сеть, синхронизация и вызовы моделей не нужны.
Каноническая база — JSON2.0.0; обратной записи из Markdown нет.

## Выбор и экспорт

Используется тот же request, что у read-only памяти: SHA графа и явные id/revision.
Включаются зависимости и связанные возражения/поправки, максимум32карточки вместе
с замыканием. Выбор не расширяется автоматически на весь архив диалогов.

```json
{
  "schema": "geek-work-memory-request-1",
  "expected_graph_sha256": "<канонический SHA графа>",
  "cards": [{"id": "theorem:sequential-probability", "revision": 1}]
}
```

```bash
python3 -B tools/geek_work_vault.py export \
  --graph YOUR_GRAPH.json --root . \
  --request .local/vault-request.json --output .local/vault-001
python3 -B tools/geek_work_vault.py verify \
  --graph YOUR_GRAPH.json --root . \
  --vault .local/vault-001 --anchor '<SHA seal из export>'
python3 -B tools/geek_work_vault.py lint \
  --graph YOUR_GRAPH.json --root . \
  --vault .local/vault-001 --anchor '<SHA seal>' --output .local/vault-lint.json
```

SHA seal — канонический хэш JSON, а не хэш файла с переводом строки. Хранить его
вне каталога экспорта. Команды создают новые выходы и не перезаписывают предыдущие.

## Состав

- `Index.md` — навигация с wikilinks; `Cards/` — карточки с устойчивыми именами по id.
- `Review.md` — видимые источниковые/редакторские ограничения, а не новый аудит.
- `Boundary.md` — связи с неэкспортированными карточками. Они существуют в графе,
  но не заменяются выдуманными заметками.
- `context.json` — полный контекст, включая проверку локальных источников;
  `request.json`, `catalog.json`, `seal.json` — воспроизводимость и контроль файлов.

Предпосылки/область действия показаны отдельно, detail/evidence/taxonomy сохраняются
без LLM-сжатия. Полные поля доступны в context.json. HTML и wikilinks из исходной
прозы экранируются; структурированные поля помещаются в защищённые code fences.
Это не универсальная защита любого Markdown-плагина и не анализ prompt injection.

Каталог физически доступен для редактирования, но изменения считаются предложением:
verify обнаружит несовпадение. Не редактировать его как единственный оригинал.
Для новой версии графа создать новый снимок. При переносе verify также нужны
исходный граф и локальные источники по относительным путям. Нет новой копии всего архива.

## Неразрешённые ссылки

lint проверяет только сгенерированные заметки и ограниченную грамматику wikilinks
вне fenced code; это не полный Obsidian parser. Он сообщает изменённые/пропущенные
заметки и неизвестные ссылки. Не делает проверку фактов и смысловой таксономии.

Необязательный `--planned .local/planned.json` принимает список будущих имён,
например `["future-note"]`. Такие ссылки классифицируются как planned_reference,
остальные — unresolved_reference. **Оба случая остаются needs_review**, файлы и
узлы графа не создаются. Выход0 lint означает сформированный отчёт, а не его чистоту:
потребитель должен проверить status. verify выдаёт отказ при изменении проекции.

Конфигурация `.obsidian` может создаваться приложением: verify явно исключает её
из аудита. Он не подтверждает безопасность плагинов/настроек. Дополнительные файлы
вне указанного набора не допускаются verify; lint не сканирует произвольный vault.
Максимум4MiB суммарного экспорта. Исходники со статусом missing/mismatch видны
как needs_review; успешная генерация заметок не повышает их достоверность.
