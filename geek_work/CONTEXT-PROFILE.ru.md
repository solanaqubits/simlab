# Локальный профиль контекста

`geek_work_context_profile.py` сравнивает полный набор карточек/связей с выборкой
по существующему запросу памяти. На обеих сторонах одна каноническая JSON-форма.
Сохраняются SHA, байты UTF-8, Unicode codepoints, выбранные и добавленные зависимые
карточки, исключённые ID и граничные связи. Отдельно измеряется retrieval envelope
с диагностикой источников. Исходники читаются только для выбранного контекста;
проверка всех provenance полного корпуса здесь не заявляется.

```sh
python3 tools/geek_work_context_profile.py \
  --graph YOUR_GRAPH.json --root . \
  --request request.json --output context-profile.json
```

Запрос имеет схему `geek-work-memory-request-1`, точный SHA графа и список
`cards: [{id, revision}]`. Устаревший граф/ревизия отклоняются; неизвестные или
повторные ID и превышение лимита замыкания проверяет штатный memory.retrieve.
Выход создаётся исключительно новым файлом. Карточки, их формулы и оговорки
не сокращаются. История событий, сырые источники, промпт и framing провайдера
не входят в сравниваемый payload. Замыкание только по записанным связям не
доказывает смысловую полноту выборки.

Это подготовка сравнения, а не модельный эксперимент. token_usage, monetary_cost
и answer_quality равны null; не вычисляем «экономию токенов» из числа символов.
Для следующего этапа понадобятся независимый корпус и измеряемый транспорт.

По решению пользователя Hermes/MiniMax не подключаем. Выбор и настройка агента,
интеграция Agentic Core из собственного агентского стека отложены в отдельный этап.
Никаких служб, расписаний и автоматической передачи vault здесь нет.

## Воспроизведение отчёта

```sh
python3 tools/geek_work_context_profile.py verify \
  --graph YOUR_GRAPH.json --root . \
  --request request.json --report context-profile.json --anchor REPORT_SHA256
```

Якорь берётся из результата первоначального profile и хранится отдельно от отчёта.
Verify заново получает выборку и проверяет весь канонический отчёт, включая размеры,
SHA инструментов и диагностику выбранных источников. Пересчитанный хэш поддельного
отчёта не заменяет воспроизведение. Неподтверждённые нулевые расходы отклоняются.

Нужны исходный граф, запрос, выбранные источники и те же версии инструментов.
Отчёт прежней версии проверяется прежним закреплённым инструментом; обновление
инструмента требует нового отчёта, а не перезаписи старых свидетельств. Это не
автономный переносимый архив и не подтверждение научного содержания.

## Бюджет до будущего модельного вызова

```sh
python3 tools/geek_work_context_profile.py preflight \
  --graph YOUR_GRAPH.json --root . \
  --request request.json --report context-profile.json --anchor REPORT_SHA256 \
  --max-context-bytes 20000 --output preflight.json
```

Перед решением отчёт полностью воспроизводится. Бюджет — целое число от 1 до
16 MiB, считается по каноническому retrieval envelope с диагностикой источников,
а не только карточкам. Равенство лимиту допустимо. Превышение или открытые issues
дают `refused`, код возврата 1 и, если указан новый output, квитанцию с причинами.
Ничего не обрезается, скрытые зависимости не удаляются. Непригодный отчёт даёт отказ
до бюджетного решения. Существующий output не перезаписывается.

`within_context_budget` не разрешает отправку данных и не квалифицирует знания.
Промпт, tool definitions, framing и ответ должны иметь отдельный резерв вызывающей
стороны. Бюджет в байтах не равен окну модели в токенах или стоимости. Этот CLI
не выполняет модельных вызовов; будущий транспорт обязан сам применять preflight.
