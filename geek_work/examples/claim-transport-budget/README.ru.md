# Второй пилот Claim Transport: ресурсный баланс

Подготовлены один план, семь кандидатов и отчёты на основе новой инженерной
спецификации Resource budget accounting 0.1 (`../../research/resource-budget/CONTRACT-0.1.md`; historical reference, not included in this public package).
Её статус — **`hypothesis` / обязательство проектирования**, а не доказанный
инвариант. Спецификация не заимствует физические или экономические утверждения
из «Proof of Light» и не подтверждает их.

## Модель учёта

`A` — доступно, `R` — зарезервировано, `S` — израсходовано, `C` — аннулировано,
`T` — выделено. Требуемое равенство:

```text
A + R + S + C = T
```

Семь предпосылок закрепляют неотрицательные целочисленные счётчики, одну условную
единицу `compute_credit`, общий бюджет и эпоху, непересекающиеся категории,
сбалансированное начальное состояние, допустимые атомарные однократные переводы
и неизменность `T` на протяжении трассы. Квантор — каждая достигнутая точка каждой
конечной допустимой трассы. Нижние границы счётчиков записаны точной строкой `0`,
а не float; единицы каждого счётчика присутствуют в карточке.

Разрешены `A → R` (резерв), `R → A` (возврат резерва), `R → S` (расход),
`A → C` и `R → C` (аннулирование). Размер перевода неотрицателен и не превосходит
исходный счёт. Аннулированные единицы сохраняются в бухгалтерской сумме;
возврат резерва не является аннулированием.

Сохранение суммы и неотрицательности при переходах и на всех трассах остаётся
**открытым обязательством доказательства**. Также не доказаны реализация,
авторизация, обработка повторов, конкурентность и восстановление после сбоев.
Проверка переноса карточки этих обязательств не закрывает.

## Фактические результаты

| Кандидат | Изменение | Результат |
|---|---|---|
| [preserved](candidates/preserved.json) | Все проверяемые поля сохранены | `contract_preserved` |
| [omit-cancelled](candidates/omit-cancelled.json) | Удалено `C` из заключения | `review_required` |
| [double-count-spent](candidates/double-count-spent.json) | Слагаемое `S` учтено дважды | `review_required` |
| [mixed-units](candidates/mixed-units.json) | `S` переведено в seconds, остальные счета — compute_credit | `review_required` |
| [drop-nonnegativity](candidates/drop-nonnegativity.json) | Убрано условие неотрицательных целых | `review_required` |
| [unsupported-proof](candidates/unsupported-proof.json) | Статус повышен до formal_reported с неподтверждённым именем теоремы | `review_required` |
| [rebound-atom](candidates/rebound-atom.json) | Под старым ID заключения изменён текст и пересчитан хеш | `invalid_input` |

Первые пять изменений с корректными новыми ID требуют review, а не автоматически
объявляются математическими контрпримерами. Валидатор сравнивает структуру и
строки; он не вычисляет бухгалтерский баланс и не выполняет размерностный анализ.
Повторное использование ID с другим текстом нарушает схему идентичности атомов.

## Происхождение и воспроизведение

Проект исходного контракта закреплён коммитом
`12c9edad88784718ec908d8e0a0bd2f8ddbd3600` частной локальной ветки SimLab.
Полные байты сохранены в [material-budget-draft.txt](source-bundle/material-budget-draft.txt),
SHA-256 `5985d0a9e93abf49624d84b97cf322d8f41599affe5e54887baf8e7d8eee7072`.
Выбранный блок — строки 20–28; диапазоны цитат считают Unicode-символы.

Из корня SimLab:

```sh
python3 geek_work/examples/claim-transport-budget/replay.py \
  --manifest-sha256 fdb0bf26aa13db9d57973a9614a4c2d4f492257b72d3d1d96d1ea88b7512a181
```

Скрипт проверяет 21 закреплённый файл данных и побайтово воспроизводит семь отчётов.
Ожидаемый хеш манифеста задаётся извне. Исходная спецификация и план имеют отдельные
хеши; кандидат их не выбирает. Сеть, Lean и генеративная модель не используются.

Во всех исходах остаются `false`: `semantic_equivalence_verified`,
`source_extraction_complete`, `kernel_replayed`, `publication_authorized`.
Автоматического импорта в граф знаний, публикации или Lean-доказательства нет.
