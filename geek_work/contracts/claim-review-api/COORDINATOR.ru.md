# Claim Review UI 0.1 — руководство координатора

Локальная реализация поверх серверного кандидата
`09b15cc352b4f6dd2454ae8881e0a2f528464fee`, ветка `claim-review-ui-20261108`.
Браузерный редактор предназначен для ручной работы с подготовленной карточкой.
Он не извлекает условия автоматически и не объявляет истинность утверждения.

## 1. Запустить контекст

Используйте команду из [руководства сервера](SERVER.ru.md#запуск-и-работа),
запуская её **из текущей UI-ветки**, где сервер умеет выдавать страницу редактора.
Параметры CLI остались прежними: снимок источника, ведомость, claim-map-пакет,
три внешних хеша, source_claim_id, source_revision и новый каталог сессии.
Ожидаемые хеши утверждаются координатором, а не берутся из кандидатской записи.

Для первого знакомства команда в серверном руководстве использует синтетическую
фикстуру `geek_work/examples/claim-adapter-ready`. Сохраняйте её исходные файлы;
новые результаты попадут в отдельный каталог сессии.

Сервер выводит JSON с `port`, `context_id`, `context_fingerprint` и `token_file`.
Эти сведения также находятся в `session.json`. Откройте в браузере
`http://127.0.0.1:<port>/`. Не открывайте HTML как `file://` и не заменяйте адрес
на `localhost`: сервер проверяет точный Host/Origin.

Вставьте context_id и токен из файла `session-token`, открытого локальным текстовым
редактором. Не добавляйте токен в URL, команды, отчёты или снимки экрана. После
подключения поле пароля очищается; токен остаётся только в памяти страницы.
После перезагрузки страницы его нужно ввести заново. Смена контекста требует
перезагрузки, перезапуск сервера — нового каталога сессии.

## 2. Сверить входы и открыть запись

Панель показывает ожидаемые и вычисленные хеши источника, ведомости и manifest.json.
Ведомость и манифест доступны для чтения в раскрывающемся блоке. Источник загружается
частями, проверяется по SHA-256 исходных UTF-8-байтов и отображается отдельно от
редактируемого документа. «Сверить якоря» повторяет запрос контекста; такая же сверка
выполняется перед проверкой/сборкой. Наблюдения за файловой системой в фоне нет.
При выявленном расхождении проверка и сборка блокируются, черновик сохранить можно.

Кнопкой «Открыть запись JSON» выберите отдельную редакторскую запись. Для положительного
контроля это `geek_work/examples/claim-adapter-ready/record.json`. Для существующего
контекста орбиты — `geek_work/examples/claim-extraction-orbit/orbit-needs-context.json`.
Контекст сервера должен соответствовать выбранным исходным материалам.

UI принимает структурированную карточку с пятью массивами ролей и четырьмя false-флагами.
Внутренние ошибки соответствия ведомости можно сохранить и передать Extraction.
Произвольный JSON-объект без структуры карточки редактируется через отдельный API/CLI,
а не этим интерфейсом. Лексический парсер UI запрещает дубли ключей, float, BOM,
непарные суррогаты и целые вне безопасного диапазона JavaScript: такие числа
отклоняются явно, не округляются. Точные математические литералы остаются строками.

## 3. Разметить контракт

Слева находится источник только для чтения, справа — атомы пяти явных ролей.
«Показать цитату» подсвечивает исходный диапазон. Для нового атома выберите роль,
выделите текст источника и нажмите «Добавить из выделения». Роль не угадывается.

Границы `[start_char, end_char)` — Unicode-кодпоинты. UI переводит DOM/UTF-16-смещения,
отвергает середину суррогатной пары и сохраняет CRLF, огласовки и исходный Unicode
без NFC/NFD-нормализации. Текст атома задаётся диапазоном источника, не свободным
пересказом. Изменение диапазона создаёт новый atom_id и хеш. Смена роли при прежней
привязке сохраняет ID. При загрузке другой записи старый ID с изменённой привязкой
также заменяется новым. Ссылки покрытия при этом **не исправляются автоматически**.

В таблице покрытия редактируются наблюдение, finding и связанные ID. Значение
`missing_extracted_atom` — отдельное обнаруженное расхождение, не синоним
`condition_absent`. Ничего не выводится из одного лишь отсутствия атома.

Числа и единицы редактируются буквально. `unit_raw`, `unit_interpretation`,
`unit_canonical` и `unit_mapping_basis` показываются отдельно. Поля точных диапазонов
чисел, покрытия, checklist, review, вопросов и границ доступны как структурированные
JSON-поля. После правки нажмите «Применить …». Незавершённые правки блокируют
сохранение и запуск; применение одного JSON-поля не стирает незавершённое другое.
«Перечитать поле» явно отбрасывает его неподтверждённую правку. Если поле уже изменено
через другой контрол, требуется перечитать его, а не затереть новое значение старым.

Переход в `ready_for_transport` требует пустых вопросов в записи **и закреплённой
ведомости**, пройденного checklist и закрытого покрытия. Удаление вопроса только
из кандидата не пересматривает ведомость. Для её изменения координатор готовит
новую редакцию с новым внешним хешем и новым контекстом. Математические
`open_obligations` могут оставаться открытыми.

## 4. Сохранить, проверить, собрать

1. **Сохранить черновик** создаёт неизменяемый серверный draft_id с SHA-256 байтов.
   При отсутствии правок сохраняются байты загруженного файла; после правок
   сериализуется новая версия. Исходник и старые версии не переписываются.
2. **Проверить** запускает Extraction на сохранённой текущей версии.
3. **Собрать** вызывает Adapter с повторной валидацией. Запись needs_context можно
   отправить, чтобы получить точную причину штатного отказа; UI не подменяет допуск.

Extraction, унаследованный reported evidence state, Adapter, Transport и свежесть
показываются раздельно. `completed` относится к исполнению задачи, `build_blocked` —
к результату допуска. У готовой фикстуры ожидаются `record_consistent`, `built`,
`contract_preserved`; у орбиты — `needs_context`, `build_blocked` с причиной
`extraction_not_record_consistent`. Не запущенный Transport остаётся `not_run`.

Любое редактирование делает предыдущую проверку `stale`. Поздний ответ для старой
версии попадает в историю как `historical`; он не подтверждает новую запись.
Изменять запись во время задачи можно, но новый запуск требует её сохранения и
освободившегося слота. При ошибке контракта, включая случайный assurance=true,
UI блокирует работу и очищает токен; исправьте причину и перезагрузите страницу.

При `built` появляются кнопки скачивания файлов. Имена сверяются с manifest.json,
байты — с хешами артефактов; источник файлов остаётся тем же локальным сервером.
Никакой отправки во внешнюю сеть нет. «Скачать запись» сохраняет текущий JSON,
«Скачать журнал» — журнал редакторских событий и квитанций с новым UUID в имени.

Сервер сохраняет версии, parent_draft_id и финальные квитанции в каталоге сессии.
Журнал промежуточных UI-правок находится в памяти страницы: **скачайте его до
перезагрузки/закрытия**. Автоматического восстановления истории браузера нет;
localStorage/sessionStorage не используются. История разрешённых вопросов хранится
в прежних версиях и журнале, а не в `unresolved_questions` готовой карточки.

## 5. Проверенный объём и ограничения

На Linux / Google Chrome 156.0.8078.79 пройдены 15 тестов в настоящем headless-браузере:
11 согласованных приёмочных сценариев и 4 дополнительных (несколько незавершённых
правок, новый ID при изменении диапазона, отказ от неточного JSON и скачивание журнала).
Положительный/отрицательный пути используют настоящий сервер и CLI. Полная матрица
редких статусов проверяется фикстурами отображения; assurance=true подставляется
только тестом в ответ fetch. Это не результаты реальных доказательств или аудита.

Emoji и CRLF проверяются на реальном исходном снимке; огласовки с CRLF и Emoji —
также на отдельном DOM-фрагменте, с сопоставлением кодпоинтов и UTF-8 SHA-256 в Python.
Тесты используют CDP, реальные DOM Selection/Range и браузерный механизм загрузки
файлов. Это не проверка во всех браузерах и не ручная приёмка независимым редактором.
Выполнена визуальная проверка снимка двухколоночного интерфейса.

Дополнительно пройдены 4 теста статических маршрутов и 199 прежних тестов сервера,
harness и CLI — **218 тестов без пропусков**. Отдельно повторены 21 положительный
пример / 73 негативных случая схем и оба внешних CLI-replay (`ready`, `orbit`).
Старые спецификации и квитанции сохранены. Первый браузерный прогон выявил неверный
селектор option; после исправления выполнена повторная приёмка, логи сохранены.

```bash
python3 -B -m unittest discover \
  -s geek_work/contracts/claim-review-api/ui_tests -v
```

Браузерные тесты требуют установленного `google-chrome` и разработческого пакета
`websocket-client`; они не нужны обычному запуску приложения. HTML/JS/CSS локальные,
без CDN, сборщика и сторонних frontend-зависимостей. CSP запрещает сторонние скрипты,
встраивание страницы и HTML-обработчики; данные выводятся через textContent.
GET разрешён только для четырёх статических путей, без содержимого сессии и токена.
POST API сохраняет прежние проверки Origin, Host, токена и квот.

Все четыре assurance-флага остаются false. Ограничитель ресурсов сервера относится
к доверенным Python CLI и не является песочницей для враждебного кода. Новый запуск
Lean, публикация веток, релизные теги и изменение графа знаний в этот пакет не входят.
