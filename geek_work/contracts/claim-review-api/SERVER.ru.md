# Claim Review Local API Server 0.1 — локальная реализация

Сервер `geek_work/tools/geek_work_claim_api_server.py` реализует шесть POST-операций
[спецификации](README.ru.md) поверх существующих Extraction и Adapter CLI.
Один сервер обслуживает один закреплённый контекст на `127.0.0.1`; браузерный UI
в этот пакет не входит. Базис реализации — локальный SimLab-коммит
`8a9b3947b23d3264c60ea7801adf0cf1b9ffd2f1`. Исторические спецификации, примеры,
схемы, harness и валидаторы сохранены без изменений.

## Запуск и работа

Запускать из корня SimLab под доверенным локальным пользователем. Python 3 на Linux;
сервер и worker используют стандартную библиотеку. Координатор задаёт внешние
якоря независимо от редактируемой записи. Пример для существующей синтетической
фикстуры (это не реальное математическое свидетельство):

```bash
python3 -B geek_work/tools/geek_work_claim_api_server.py \
  --source-snapshot geek_work/examples/claim-adapter-ready/source.txt \
  --source-sha256 d26f1ffb801b4c2531a7afa1d61d5ceb073426db50ec018e5eaed146ae4483a2 \
  --expectations geek_work/examples/claim-adapter-ready/expectations.json \
  --expectations-sha256 d89b842e18302492a04804878c586f15cf0f0d0e7ce4786a0f3e0acda435f72b \
  --claim-map-bundle geek_work/examples/claim-adapter-ready/source-bundle \
  --claim-map-bundle-sha256 fd6ef4be66849d2c071b680a4cdd060999ec2b2c24b183e6bc41fdd0ce225057 \
  --source-claim-id synthetic-balance --source-revision 1 \
  --session-dir /tmp/claim-review-session-new
```

Каталог сессии обязан отсутствовать до запуска. Порт выбирается ОС, либо задаётся
через `--port`; адрес привязки не настраивается. Стартовый JSON и `session.json`
содержат порт, context_id, fingerprint и путь к файлу токена, но не сам токен.
Каталог имеет права 0700, `session-token` — 0600. Токен не передаётся в URL,
аргументах CLI, журналах и квитанциях. Автоматического восстановления сессии после
перезапуска нет; старый каталог сохраняется как история, новая сессия использует
новый каталог и токен.

Запросы требуют канонических Host/Origin и Bearer-токена. Сервер не доверяет
Forwarded/X-Forwarded-* при определении адреса. Все ответы имеют `no-store`.
Ограничены чтение заголовков и тела, глубина JSON, длина целых, Base64, размер и
количество версий. Непарные суррогаты, BOM, дубли ключей и float отвергаются.
Синтаксически корректный объект с ошибками схемы Extraction сохранить можно.
Сырые байты черновика не нормализуются; хеш привязан к ним.

`checks` и `builds` проверяют закреплённую версию и создают задачу. Повтор того же
request_id с теми же байтами возвращает прежний результат; с другими байтами —
409. В контексте не более одной задачи queued/running; отдельной очереди нет.
Новая задача при занятом слоте получает `409 context_busy`, идемпотентный повтор
первой остаётся допустимым. Обработка HTTP-запросов последовательна и ограничена
таймаутами; CLI выполняется в отдельном рабочем потоке/процессе.

Перед допуском и перед подготовкой задачи повторно сверяются источник, ведомость
и весь claim-map-пакет. CLI читает отдельный снимок внутри каталога задачи. Новый
черновик не меняет уже запущенную версию: поздняя квитанция содержит исходные
`draft_id`, SHA-256 и fingerprint. Сервер не присваивает текущему черновику статус
проверенности; отображение `historical/stale` остаётся обязанностью будущего UI.

## Процессы, квоты и регистрация

Доверенный worker `geek_work_claim_api_worker.py` запускается фиксированным списком
аргументов без shell. HTTP не может задавать исполняемый файл, пути или CLI-флаги.
Лимиты из [limits.json](limits.json): 60/180 секунд для check/build, SIGTERM с
ожиданием 2 секунд и затем SIGKILL с ожиданием 2 секунд; stdout и stderr читаются
одновременно с пределом 256 KiB каждый. При аварии процесса, превышении лимита
или несовместимой квитанции задача получает `failed`. Штатные отрицательные
результаты валидаторов получают `completed` с исходным статусом и кодом CLI.

На задачу резервируется 64 MiB в пределах сессии 512 MiB. Worker учитывает байты
до записи через используемые доверенными CLI Python file API и ограничивает
размер файла через RLIMIT_FSIZE. В бюджет включены входные копии, выходы, два
потока и запас для служебных файлов. Учёт консервативный: повторная запись
расходует квоту повторно, активная задача сохраняет полный резерв. Manifest
включён в предел 16 MiB входного bundle. Артефакт ограничен 16 MiB.

Это **ограничитель ресурсов фиксированных доверенных Python CLI**, не песочница
для произвольного или враждебного кода. Он использует Linux `/proc`, сигналы и
RLIMIT_FSIZE; внешние процессы, нативные расширения, меняющие файлы в обход
поддерживаемых API, и постороннее изменение каталога сессии тем же OS-пользователем
не входят в модель изоляции. Публичное развёртывание не поддерживается.

После CLI сервер повторяет тот же детерминированный код и сверяет все выходные
байты, статусы, коды выхода, manifest и привязки. Это повтор реализации, **не
независимый аудит**. При любом расхождении, в том числе assurance=true, пакет
не регистрируется. Регистрация артефактов атомарна относительно выдачи API:
сначала проверяются все файлы и записывается финальная квитанция, затем публикуются
UUID в локальном контексте. Ошибка записи квитанции оставляет failed и не открывает
частичный пакет. Неуспешные результаты не дают доступ к произвольным файлам задачи.
Чтение артефакта повторно сверяет SHA-256 и возвращает не более 65 536 байт Base64.

## Воспроизведение проверок

Для схем и существующего harness нужна установленная разработческая зависимость
`jsonschema` (в данном проходе 4.10.3). HTTP-сервер не импортирует её.

```bash
python3 -B -m unittest discover \
  -s geek_work/contracts/claim-review-api/server_tests -v
python3 -B geek_work/contracts/claim-review-api/server_tests/replay.py \
  --output /tmp/claim-review-server-evidence-new
```

Replay запускает отдельные процессы сервера и неизменённого harness для `ready`
и `orbit`, сохраняет только очищенные квитанции, удаляет временные сессии и токены.
Каталог свидетельств должен быть новым. В готовом сценарии получены
`record_consistent → built → contract_preserved`; в орбитальном —
`needs_context → build_blocked`, `package_available=false`, без плана/кандидата.
Это проверка настоящего HTTP-сервера и реальных CLI, в отличие от прежних
28 самопроверок клиента с заглушками.

37 серверных тестов включают реальный готовый сценарий, занятый слот, таймаут и
SIGKILL, остановку дочернего процесса, переполнение stdout/stderr, предзаписные
квоты файла/совокупной записи, резервирование диска, rate limiting, подмену якорей,
ошибки HTTP/JSON/Base64, позднюю квитанцию старой версии и отказ при assurance=true.
Управляемые сбои внедряются только Python-тестами через внутренние объекты Runner,
mock и сокращённые тестовые лимиты. HTTP/CLI переключателя fault injection нет.
Тест резерва диска моделирует занятость; весь физический диск не заполнялся.
Проверка поздней квитанции проверяет привязку сервера, не поведение отсутствующего UI.

Отдельно повторены 134 существующих CLI-теста, 28 самопроверок harness и проверка
21 сообщения / 73 негативных случаев JSON Schema. Всего 199 unit/integration-тестов
в непересекающихся наборах; 59 HTTP-обменов внешнего replay учитываются отдельно,
не прибавляются к числу тестов. Проверки не являются аудитом всей SimLab.

Во всех выдаваемых отчётах четыре assurance-флага остаются false. Lean не
запускается; истинность первоисточника, полнота редакторского извлечения и смысловая
эквивалентность этим сервером не доказываются. UI, граф знаний, публичные ветки,
релизные теги и автоматическое извлечение не изменяются этим компонентом.
