# Очередь проверки внешних ссылок

Это офлайн-подготовка предметного аудита, а не проверка доступности страниц.
Инструмент использует штатную выборку memory с зависимостями и существующий индекс
строковых полей. Сохраняются ID/ревизия/SHA карточки, JSON Pointer, SHA строки,
точный литерал и его начало/конец в Unicode codepoints. Повторные упоминания
сохраняются; unique_literals — отдельное число, без удаления происхождения.

```sh
python3 tools/geek_work_references.py scan \
  --graph YOUR_GRAPH.json --root . \
  --request REQUEST.json --output NEW_REFERENCES.json
python3 tools/geek_work_references.py verify \
  --graph YOUR_GRAPH.json --root . \
  --request REQUEST.json --report NEW_REFERENCES.json --anchor REPORT_SHA
```

Запрос тот же, что у memory/context-profile. SHA отчёта сохраняется отдельно.
Verify повторяет выборку и сверяет отчёт с текущими источниками и версиями
инструментов. Источник с hash_mismatch/missing и review-флаги остаются видимыми;
даже изменение между двумя неверными версиями источника меняет context SHA.
Устаревший SHA графа или выбранная ревизия отклоняются.

Флаги — подсказки для ручного выбора следующего шага: mutable_git_reference,
pinned_git_syntax, versioned_identifier_syntax, credentials_present,
private_or_local_literal, malformed_url и ambiguous_trailing_punctuation.
40 hex-символов в URL не доказывают существование коммита или неизменность сайта;
версионный идентификатор не означает peer review. IP/localhost-флаг основан только
на написанном адресе; DNS не разрешается, безопасность назначения не гарантируется.

Парсер намеренно узкий: регистрозависимые литералы http:// и https:// в строковых
полях выбранных карточек. Он не обещает охват HTML/PDF, относительных ссылок или
содержимого всех source-файлов. Конечная пунктуация не удаляется: спорный литерал
остаётся точным и помечается для рассмотрения. Исходные карточки не правятся.
Лимиты: штатные 32 карточки с замыканием, 4096 строковых полей, 4 MiB текста и
256 вхождений ссылок. Превышение даёт отказ, без тихой обрезки. Output новый.

Availability и content_verification всегда not_checked. Нет HTTP/DNS, переходов,
редиректов, загрузки файлов или исполнения указаний из текста. Отчёт приватный:
литералы могут содержать пользовательские параметры/credentials. Для следующего
этапа нужны явный отбор публичных адресов, проверка прав/приватности и ограниченная
проверка первоисточников. До этого нельзя считать внешние ссылки проверенными.

## Сводка без литералов

`summarize` принимает те же `--graph`, `--root`, `--request`, `--report`,
`--anchor`, что `verify`, и необязательный новый `--output`. Сначала полностью
проверяет якорь и воспроизводимость, затем выводит только количества карточек,
вхождений, уникальных литералов, повторов, флагов и вхождений с проблемами источников.
URL, учётные данные, параметры запроса, ID карточек, пути и хэши источников
в сводку не включаются. Ошибочный или устаревший отчёт не получает сводку.
Количество повторов — вхождения минус уникальные литералы; флаги считаются по
вхождениям, поэтому одна ссылка может попасть в несколько категорий.
Даже агрегаты могут быть приватными; автоматической публикации нет.
После изменения версии инструмента старый отчёт сохраняется как история;
для нового replay требуется новый scan, без перезаписи старых артефактов.
